<task type="auto">
  <name>Task 1: Implement graph construction from road geometries</name>
  <files>src/data/graph_builder.py</files>
  <action>
Implement GraphBuilder class:

1. **build_graph(roads: GeoDataFrame) -> nx.Graph**
   Main method that converts LineStrings to NetworkX graph.

   Algorithm:
   a) Extract all unique endpoints and intermediate vertices from LineStrings
   b) Identify intersection points (vertices shared by multiple LineStrings)
   c) Create nodes for all intersections and road endpoints
   d) Create edges between consecutive nodes along each LineString
   e) Calculate edge weights as geodesic distance in meters

   **Critical for correct topology:**
   - Use coordinate rounding/snapping to handle floating-point precision issues
   - Snap nearby endpoints (within ~1 meter) to same node - roads may not perfectly connect
   - Handle multi-part geometries (MultiLineString) by processing each part
   - Edge weight = sum of segment lengths along the original LineString between nodes

2. **Node attributes:** Store (x, y) coordinates as node attributes for later spatial queries

3. **Edge attributes:** Store:
   - `weight`: distance in meters (for shortest path algorithms)
   - `geometry`: original LineString segment (for visualization/export later)

**Implementation approach:**
- First pass: collect all vertices, round coordinates to ~6 decimal places
- Build a dict mapping rounded coords to node IDs
- Second pass: for each LineString, walk vertices and create edges between nodes
- Use Shapely's length property with proper CRS for accurate distances

**Avoid:**
- Don't create a node for every vertex - only intersections and endpoints
- Don't assume roads connect perfectly - use snapping tolerance
- Don't use Euclidean distance - use geodesic/projected distance
